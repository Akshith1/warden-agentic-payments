## Findings

1. **The Approval agent spotted the test pattern.** It escalated both OJC
   invoices without being told to: "Four payments in 24 hours and five
   recent identical amounts create a material duplicate-payment risk", and
   "Five identical 64.50 MYR payments in the last 24 hours create a
   potential duplicate-payment concern". Each invoice had a new number, so
   the ledger's duplicate check, which matches on vendor and number, would
   have let them through. This is the kind of judgment the agents are for.
   It also suggests a coded rule worth adding: repeated identical amounts to
   one vendor in a short window.
2. **The stop came too late for a payment in its hold.** The first attempt
   to stop `OJC-2026-0470` mid-hold missed: the commit was at 1:01:41 and the
   stop at 1:02:38. Twenty seconds is short when switching browser tabs.
   The hold-time stop is covered by the automated tests and the local end to
   end run. To try it by hand, set `SETTLEMENT_HOLD_SECONDS=90` for the
   session.
3. **A stopped run's trail.** When the kill switch stops a payment in its
   hold, the run's own trail shows only the later, successful hold; the stop
   itself is in the audit log ("Stopped: kill switch is on…"). The audit
   log is the record by design. Showing stops in the run trail too is a
   possible console improvement.
4. **Long guardrail reasons in the Runs list.** Now one line ("Guardrail:
   instructions hidden in the document…"); the full words found are on the
   run page.
