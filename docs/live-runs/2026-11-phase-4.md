# Phase 4 live run (November 2026)

Phase 4 runs on the same Windows 11 machine, with real models and the
Extraction prompt promoted in phase 2 (v3). After the rebuild, all seven
services reported healthy, including `warden-policy`. That service only
becomes healthy after validating the whole policy set, so the set shipped in
`policies/` was accepted on the machine. Everything below comes from the
console and PowerShell; nothing is reconstructed.

## Findings and what changed

1. **The critic took 58 s** while four runs called the same Groq route at
   once (step 4), against about 4 s for the approval step. Nothing failed.
   Phase 8's per-agent keys and budgets, and phase 9's tracing, are where
   provider latency becomes visible per agent.
2. **Waiting runs showed no reason in the Runs list.** The reasons were only
   on the run page. A waiting run now records them as its `status_reason`,
   so the list's **Why** column shows, for example, "policy: the vendor
   already had 3 payments approved in the last 24 hours, so a person must
   approve".
3. **Docker Desktop was not running** at the first attempt
   (`failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`).
   Starting Docker Desktop fixed it; no change needed.
