# Phase 6 live run (November 2026)

Phase 6 runs on the same Windows 11 machine with Docker Desktop, Keycloak
26.6.4 and real models. Everything below comes from PowerShell and the
console; nothing is reconstructed.

## Starting Keycloak

The first start failed:

```
✘ Container warden-keycloak-1  Error dependency keycloak failed to start
...
Caused by: java.nio.file.AccessDeniedException: /opt/keycloak/data/h2/keycloakdb.trace.db
ERROR: Could not open file /opt/keycloak/data/h2/keycloakdb.mv.db
```

The named volume was mounted at a path the image doesn't have, so Docker
created it owned by root, and Keycloak (uid 1000) couldn't write its
database. A one-off `keycloak-data-init` step now hands the volume to
uid 1000 before Keycloak starts. After that:

```
✔ Container warden-keycloak-data-init-1 Exited
✔ Container warden-keycloak-1           Healthy     31.8s
...
Realm 'warden' imported
Keycloak 26.6.4 on JVM (powered by Quarkus 3.33.2.1) started in 15.431s.
```

Before shipping, the realm had been tested against a local Keycloak of the
same version. That test found that a user imported with a `temporary`
password is not asked to change it. The users now carry the
`UPDATE_PASSWORD` required action, and script sign-ins with the first
password are refused ("Account is not fully set up").

## An approver approves by role

Signed in as `clerk` (submitter), a Kestrel Print Works invoice for MYR
45.00 was submitted. As a first-seen vendor it went to a person. Clerk
could see it but had no decision form. Signed in as `amira` (submitter,
approver), the run was approved:

```
1 Guardrail screened the text        12:06:25 PM             No instructions to the AI found by the rules or the safety model
2 Extraction agent read the invoice  12:06:27 PM +1.7 s      Prompt v3, promoted by the evaluation gate
3 Risk agent scored it               12:06:28 PM +0.9 s      low risk (0.25), sent to a person: first-seen vendor
4 A person decided                   12:09:00 PM +2 min 32 s Approved by Amira Approver
5 Policy engine checked it           12:09:00 PM +0.0 s      Allowed for amira (approvers-may-approve)
6 Ledger dry run                     12:09:00 PM +0.1 s      Would balance; nothing written
7 Settlement hold                    12:09:00 PM +0.0 s      20 s to stop it before money moves
8 Ledger commit                      12:09:20 PM +20 s       Posted as transaction 29
```

The approver's name in step 4 comes from her Keycloak token. Step 5 names
the Cedar rule that allowed it: the approver role, for an amount within
50,000.00.

## Four eyes

Still signed in as `amira`, an Osprey Courier Services invoice for MYR
30.00 was submitted, and she then tried to approve it herself. The decision
form showed:

```
you can't approve this one: you submitted this invoice, so another person must approve it
```

The run stayed at **Needs your decision**, with nothing written to the
ledger. Amira holds the approver role and the amount is small, so the only
rule that stopped her is `four-eyes` (`policies/08-four-eyes.cedar`). It
compares her username with the run's recorded submitter, both taken from
verified tokens.

## Findings

1. **Keycloak's volume ownership** (above). Fixed with the
   `keycloak-data-init` step.
2. **Temporary passwords don't expire on import** (found before shipping,
   above). Fixed with `requiredActions: ["UPDATE_PASSWORD"]`.
