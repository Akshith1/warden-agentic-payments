# Phase 7 live run (November 2026)

Phase 7 runs on the same Windows 11 machine as the earlier phases, with real
models, per-agent gateway keys (phase 8) and Keycloak sign-in (phase 6).
`warden-pii` runs with a read-only filesystem, as an unprivileged user, on an
internal network with no route out. Everything below comes from the console,
PowerShell and the service log; nothing is reconstructed.

## First attempt: failed closed

The first Kestrel invoice (`K-2026-002`) stopped at the first step:

```
Failed, can retry   error: HTTPStatusError: Server error '500 Internal Server Error'
                    for url 'http://warden-pii:8000/mask'
```

The vendor column read "Not read yet": no agent and no model had seen the
invoice. The PII service log showed why:

```
PermissionError: [Errno 13] Permission denied:
'/opt/tldextract/publicsuffix.org-tlds/de84b5ca2167d4c83e38fb162f2e8738.tldextract.json.lock'
```

Presidio's email recognizer calls `tldextract`, which takes a lock file in its
cache even to read it. The container's root filesystem is read-only, so every
`/mask` call failed. The run failed closed, which is the intended behaviour
when masking is unavailable.

**Fix (PR #19).** `tldextract` now uses the domain list bundled with the
library, with no disk cache and no download, and the build-time cache warm-up
was removed. A test blocks file locks and network access and checks an email
is still masked. After the rebuild, **Retry from the failed step** continued
the same run.

## The retried run

`K-2026-002`, Kestrel Print Works, MYR 90.00. Trail as shown by the console:

```
1 Personal data masked            3:10:48 PM          Replaced before any model saw the text: 1 person,
                                                      1 phone number, 1 bank account
2 Guardrail screened the text     3:10:49 PM +1.5 s   No instructions to the AI found by the rules or the safety model
3 Extraction agent read the invoice 3:10:51 PM +1.4 s Prompt v3, promoted by the evaluation gate
4 Risk agent scored it            3:10:52 PM +1.6 s   medium risk (0.60), sent to a person: limited history:
                                                      1 prior payment(s), auto-approval needs 2
```

**Pay to** read `Maybank account 5140-9876-5432`: the real value, put back
after the models answered. **What the models saw**:

```
Cashier: <PERSON_1>
Queries: siti.aminah@kestrelprint.example  Tel: <PHONE_NUMBER_1>
Pay to Maybank account <BANK_ACCOUNT_1>
```

**Finding: the email address was not masked**, and it carries the cashier's
name. Presidio's email recognizer also requires the domain to end in a public
suffix; `.example`, `.internal` and `.local` are not, so such addresses were
skipped. For masking, that check fails in the unsafe direction.

**Fix (PR #20).** Presidio's email recognizer is replaced by one that masks
anything shaped like an email address, whatever its domain, with tests for
three kinds of domain.

## Findings

1. **Read-only containers expose library side effects.** `tldextract`
   writing a lock file passed every test on a writable disk. CI does not run
   the service read-only, so the new test simulates it.
2. **Presidio's email check is tuned for finding, not hiding.** For masking,
   anything shaped like an email address is now masked. Other built-in
   recognizers with validation (credit cards with a checksum, IBANs) are
   worth the same review in phase 7b.
3. **The risk score varied on near-identical invoices**: 0.60 for `K-2026-002`
   and 0.15 for `K-2026-003`, same vendor, same history. Both went to a person
   for the same code rule (limited history), so the outcome did not change.
   Phase 9b's tracing is where this variance becomes measurable.
