## Findings and what changed

1. **Groq validates tool-call arguments server-side.** The model returned
   `currency: null` for a receipt that prints no currency; the schema required
   a string, and Groq answered with a hard 400 that bypassed Instructor's
   re-ask (`39a80e88`). Fixed in phase 1: currency is optional and Instructor
   runs in JSON mode, so validation happens client-side and is retried.
2. **OpenAI API credit is separate from ChatGPT.** `4e02ace2` failed with
   "You have no credits remaining" at the Approval step, the first step that
   calls OpenAI. Phase 2: such runs are `failed` (not `blocked`) and
   `POST /runs/{id}/retry` continues from the failed step.
3. **Vendor name quality.** For `bcd50415` the model put the cashier's name
   and a "COPY" stamp into the vendor name. A second receipt from the same shop
   would not match the ledger's vendor history. Phase 2: the prompt says what a
   vendor name is, and the promotion gate scores vendor names strictly.
4. **Implicit policy in model judgment.** The Approval agent escalated
   `d074622f` for two reasons that are business rules, not judgment: "the
   invoice currency is missing" and "only one prior payment". Phase 2 makes both
   explicit (`LEDGER_CURRENCY`, `MIN_PRIOR_PAYMENTS`), enforces them in code
   before the model is asked, and tells the agents they are already enforced.
5. **Startup and environment issues on Windows**, all fixed: no `sh` in
   PowerShell (`compose.ps1`), a startup race with Postgres (services wait for
   the database), a root-owned dataset cache volume, and dataset images decoded
   without need.

Not yet shown live: the fully automatic path (no human). It needs a vendor
that meets `MIN_PRIOR_PAYMENTS`, which phase 2 makes explicit.
